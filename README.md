# 港股 IPO 项目排程器

> 当前入口为排程器，界面 v0.11、引擎 v0.10.0。默认包为129事件、7条线、23线程；规则与中美港日历从 Supabase 已发布版本读取，失败时回退缓存/内置包。方案仍只保存在本机。
>
> **接手项目先读 [HANDOFF.md](HANDOFF.md)**；云端说明见 [db/README.md](db/README.md)。正式站：https://ipo-timeline-app.vercel.app/ 。下文是早期本地版历史说明，其中「124事件」「没有云服务」「仅周末日历」不再代表现状，以交接说明和当前代码为准。

本地开发无需 npm 安装或构建。可直接打开 `index.html`，或运行 `python3 -m http.server 8000` 后访问 `http://localhost:8000/`。不同访问来源不共享本机方案，迁移前请导出完整 JSON。

## 早期本地版说明（历史记录）

这是一个无需安装、无需联网的本地事件信息采集工具。

## 使用方法

1. 双击打开 `index.html`。
2. 在左侧依次新增条线、线程和事件。
3. 为每个事件填写名称、归属及前置关系和时间间隔。
4. 右侧会自动检查循环依赖、日期区间和锚点连接情况。
5. 定期点击“导出 JSON”保存独立备份。

左侧项目结构支持按条线、线程逐级收起或展开，也可以使用“全部收起 / 全部展开”。折叠状态单独保存，不会改动已录入的项目数据。

数据默认保存在当前浏览器的本机存储中。清理浏览器数据、更换浏览器或更换电脑前，请先导出 JSON。

排程引擎及字段定义见 `ENGINE_SPEC.md`。

## 本地排程器 v0.2

2026-10-29 核心修订：原规则与方案不自动覆盖。已有方案可点击“基于当前规则创建修订副本”，或导入 `规则修订_2026-10-29/未命名港股_IPO_排程方案_核心修订版.json` 查看待确认预览。逐条修改及假设见该目录的 `修订说明与逐条清单.md`。

规则支持空目标、无最长间隔及自然月；采集器已同步支持，空值不是0。新优化器优先工作日，并综合权衡错周、目标间隔和改期成本；默认不会仅因旧方案仍可行就停止优化。需要完全保留可行旧版时，选“仅修复硬冲突”。人工锁定仍是硬条件。

直接用浏览器打开同目录下的 `scheduler.html`，或在采集器顶部点击“项目排程 ↗”，复制当前规则快照进入排程器。整个应用没有外部脚本或云服务依赖，所有计算均在本机进行。

1. 选择“载入补充初稿”使用本次124事件库，或导入自己的规则JSON。载入另一份规则会新建方案，不覆盖已有规则快照。
2. 填写各锚点日期。当前事件库的启动会、A1、申报基准日均需要输入日期。修订库增加报告期末至审计报告初稿的就绪条件，但未完成财务资料有效期的全部校验。
3. 点击“生成 / 重新试排”。引擎先满足全部硬区间、锁定及固定日期，再优先工作日、综合优化同线程错周与目标间隔。
4. 查看按周表或清单；点击事件可查看规则、目标偏移、单独可调整范围，并设置日期锁定。设置锁定后需要重新试排。
5. 结果先进入预览，点击“采用此版本”才替换已确认排程。保留最近8个确认版本，可恢复。
6. 导出方案JSON用于完整备份，或导出日期表CSV用于审阅。CSV不是完整规则备份。

### 数据保护

- 采集器仍使用原存储键 `ipo-schedule-rule-collector-v1`。排程器独立使用 `ipo-scheduler-plans-v1`，不回写采集器。
- 浏览器、文件路径和访问地址可能隔离本机存储。直接打开文件和通过本机HTTP地址打开，可能看见不同方案；通过导出/导入迁移，不假定它们共享数据。
- 采集器入口用窗口消息传递快照，避免依赖不同本地文件能直接共享存储。若浏览器阻止新窗口，请手动打开排程器并导入规则JSON。
- 新文件导入保留旧方案。请定期导出备份；浏览器存储满时页面会提示，不将内存中尚未保存的数据冒充已保存。

### 当前能力边界

- 默认日历只排除周末，没有内置香港、内地或美国公众假期。导入真实日历之前均属于试排；日历覆盖不足时明确警告。
- “日历与计算范围”中可下载格式示例。须自行填入真实来源版本、完整覆盖区间、节假日和补班日后导入；不能把空白示例当真实日历。
- 自然日与工作日分别按规则处理。工作日偏移不计出发日；0日偏移保留同一天；反向关系通过合法日期集合求解。
- 同线程错周为偏好，不保证全部事件不同周；同日硬关系、固定日期和硬上下界优先。
- 错周优化支持联动移动一串受影响事件，避免只是把同周冲突转移到另一线程。若两个事件的全部候选日都被硬条件限制在同一周，结果会说明无法错开。
- 新建方案默认启用“A1仅安排在项目工作日”，这是可取消的方案级硬限制，不回写事件库，也不是法规校验。旧方案保留原设置。未导入公众假期时，该限制仅排除周末。
- 优化器给出经过独立复核的可行解，使用限时启发式优化，不承诺偏好全局最优。到时未找到结果会说明未判断完成，不误报无解。
- “试算最早A1”只释放所选A1锚点（及该锚点的人工锁），其余固定日期保留。最早日期仅相对于当前规则、日历和搜索范围成立。
- 冲突说明经过限时缩减，不保证为最小冲突集。未实现“反求最晚启动日”、人员容量约束、法规期限自动核验或已完成事件管理。
- 原采集器的结构检查仍将所有前置环作为提示；排程器只将硬前置环作为模板错误，软关系可违反。

### 验证

运行 `node scheduler-tests.cjs`，覆盖完整124事件库、过早A1、释放A1、锁定重排、混合日历、同日关系、软条件、数据保留，以及随机小图与穷举结果对照。日期仅为功能验证假设，非真实项目目标。

开发时可临时在本机启动静态预览；最终使用不要求保留预览服务。设计讨论稿见 `SCHEDULER_DESIGN_DRAFT.md`，其中部分后续能力尚未实现，以本节边界为准。
