# IPO 云端规则库与日历（一期）

专用 Supabase：`mffcztvzoaayihqttrjo`，新加坡。仅存公共默认规则与公共日历，不存项目日期、锁定、排程结果或用户资料。

## 数据与权限

- `ipo_library_releases`：规则、会议议程、三地日历组成一个原子版本包。草稿可修改；发布后不可修改或删除。
- `ipo_library_channels`：`production` 指向一个已发布版本，可切换到历史发布实现数据回退。禁止指向草稿。
- RLS 已启用。匿名用户和普通登录用户只能读取已发布包及正式指针，没有 INSERT/UPDATE/DELETE 权限。前端只使用公开 publishable key，不含管理或 service-role 密钥。
- 远程迁移 `20261030092449_ipo_library_releases` 已应用；`library-schema.sql` 是该迁移的可审阅源文件，不是本地 CLI 生成的迁移历史。

## 前端行为

1. 启动时仅通过 GET 获取正式指针，再读取对应版本包；检查引擎兼容、事件引用、日历日期及议程引用。
2. 新方案复制该规则和日历，保存 `ruleRelease` 与 `calendarRelease` 的版本标识。
3. 请求失败时使用上次已发布缓存，缓存也不可用时使用程序内置包；状态会明确提示。
4. 旧方案不自动升级；本机自定义规则及日历不被覆盖。现有项目方案仍只保存在本机。
5. “刷新云端已发布版本”仅刷新今后新建方案的默认数据，不改当前方案。

## 管理发布（当前仅受权管理工具 / Supabase 控制台）

当前没有开放网页写入或管理员登录。规则采集器和 JSON 导入只改本机测试数据，不会自动发布。

导出当前代码自带的公开默认包：`node scripts/export-library.cjs`。输出不读取项目 JSON 或浏览器存储。修改后的包在发布前应通过 `IPOLibraryCloud.validate`、引擎结构校验及短/中/长窗口试排。

发布步骤：插入 `draft` 版本包 → 校验 → 在同一数据库事务内将该草稿改为 `published` 并设置 `published_at`，然后把正式指针指向它。后续更正创建新版本，不修改已发布内容。切换指针属于正式数据发布，需要用户批准；不必重新部署前端，除非版本包要求更新引擎。

正式网页连接的是只读正式数据；预览站点同样只读，因此不会通过预览写入正式数据。将来增加写入后台时，应另设测试通道及管理员权限，不沿用公开客户端写入。
